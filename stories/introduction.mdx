# Lumen

The design system of slashome. One implementation, used the same way from React, Vue, Svelte or plain HTML.

## Two ways to use a component

- **A CSS class, no JavaScript.** Load the stylesheet and put the class on native HTML: `.lu-button`, `.lu-icon-button`, `.lu-badge`, `.lu-tag`, `.lu-field`, `.lu-input`, `.lu-date-input`, `.lu-textarea`, `.lu-native-select`, `.lu-switch`, `.lu-checkbox`, `.lu-radio`, `.lu-radio-card`, `.lu-kbd`, the page states, `.lu-alert`, `.lu-skeleton`, `.lu-progress`, `.lu-breadcrumb`, `.lu-pagination`, `.lu-stepper`, `.lu-markdown`, `.lu-data-table`, `.lu-mark`, and the utilities `.lu-visually-hidden`, `.lu-truncate`, `.lu-line-clamp`, `.lu-spin`. The data table sorts with `sortRows` and `storedSort()`. The classes sit in cascade layers: an application overrides them without `!important`.
- **A custom element, imported once.** Components that hold state (open or closed, a selection, the focus) are tags that work in any framework: `<lu-dialog>`, `<lu-sheet>`, `<lu-confirm-dialog>`, `<lu-tooltip>`, `<lu-hover-card>`, `<lu-select>` with its `<lu-option>`, `<lu-multi-select>`, which takes its options as data, `<lu-segmented>`, `<lu-tabs>`, `<lu-toaster>`, `<lu-markdown>`, `<lu-highlight>`, `<lu-drag-area>` with `<lu-draggable>` and `<lu-drop-zone>`, `<lu-file-drop>`, `<lu-tag removable>`, `<lu-icon>`. Import `@slashome/lumen` for all of them, or `@slashome/lumen/<name>` for one.

The Storybook is sorted by use: Foundations, Actions, Form, Feedback, Navigation, Data, Overlays. Each page says under its title how the component is used, and its props table is read from `custom-elements.json`. The shared vocabulary of names, sizes, variants and events is on [Prop conventions](?path=/docs/foundations-prop-conventions--docs).

## Install

```sh
pnpm add @slashome/lumen
```

```js
import '@slashome/lumen/lumen.css'
import '@slashome/lumen'
```

Lumen ships no text: register the generic labels once at start-up, for each language, with `registerLumenMessages()` (see [Labels](?path=/docs/foundations-labels--docs)). An element without its labels logs an error and leaves the text out.

`@slashome/lumen` defines every element. A page that uses a few imports them one by one, `@slashome/lumen/<name>`: `import '@slashome/lumen/select'` defines `<lu-select>` and its `<lu-option>`, without the Markdown or drag-and-drop code. A single component's CSS is `@slashome/lumen/css/<name>.css`.

## Theme

Two colors, set on `:root` at run time; every other shade derives from them, in light and dark.

```css
:root {
  --lu-theme-primary: #3760c9;
  --lu-theme-secondary: #3760c9;
}
```

Dark mode follows `data-appearance="dark"` on the root element, or the system when the attribute is absent.

## React

```tsx
import { Button, Dialog, toast, Toaster } from '@slashome/lumen/react'
```

The adapter keeps React's idioms: `open` and `onOpenChange`, `value` and `onValueChange`. Given `open` or `value`, a component is controlled; without it, the element changes itself and still calls the callback.

`Tooltip` and `HoverCard` do not wrap their trigger: they name it with `htmlFor`, as `<label htmlFor>` does, and the trigger carries the id, best made with `useId()`.

```tsx
const id = useId()

<Button id={id} variant="ghost" size="icon"><Icon name="copy" label="Copy" /></Button>
<Tooltip htmlFor={id}>Copy the command</Tooltip>
```

## Vue

```ts
import { isLumenElement } from '@slashome/lumen/vue'

vue({ template: { compilerOptions: { isCustomElement: isLumenElement } } })
```

```vue
<lu-select label="Status" :value="status" @lu-value-change="status = $event.detail.value">
  <lu-option value="todo">To do</lu-option>
</lu-select>
```

`@slashome/lumen/vue` also exports `LuDialog`, `LuSelect` and the other elements whose state the user changes, for `v-model:open`, `v-model:value` and `v-model:selected`: bound, the component is controlled; unbound, the element changes itself. Import the elements themselves as for any other use.

```vue
<LuDialog v-model:open="editing" heading="Edit T104">…</LuDialog>
```

A tooltip or a hover card names its trigger with `for`; a template ref given to `:anchor` does the same for a trigger in another shadow root.

```vue
<button id="copy" class="lu-icon-button"><lu-icon name="copy" label="Copy" /></button>
<LuTooltip for="copy">Copy the command</LuTooltip>
```

## Plain HTML

```html
<button class="lu-button lu-button--outline">Cancel</button>
<button id="copy" class="lu-icon-button"><lu-icon name="copy" label="Copy"></lu-icon></button>
<lu-tooltip for="copy">Copy the command</lu-tooltip>
```

## Icons

`<lu-icon name="close">` draws a semantic name mapped to an Iconify id, embedded at build time: no request at run time. An application adds its own names with `lumen-icons <mapping.json> <output.ts>` and `registerIcons()`.

## Events

Every event is a `CustomEvent` named `lu-*`, bubbling and composed: `lu-open-change`, `lu-value-change`, `lu-selected-change`, `lu-files-change`, `lu-confirm`, `lu-navigate`, `lu-drag-end`, `lu-reject`, `lu-remove`, `lu-open`. The type of each `detail` is on the page of its element.

An element changes its own state when the user acts: a dialog closes on Escape, a select takes the option picked. It fires a cancelable `lu-*-change` first; cancel it and set the property to control the element yourself. The rule and the sources are on [Prop conventions](?path=/docs/foundations-prop-conventions--docs).
