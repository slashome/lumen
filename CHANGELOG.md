# @slashome/lumen

## 0.2.0

### Minor Changes

- 68e8114: `lu-tooltip` and `lu-hover-card` no longer wrap their trigger: they name it with `for="<id>"` (property `htmlFor`), or take it in the `anchor` property, and set `aria-describedby`, or `aria-expanded` and `aria-controls`, on it themselves. Their default slot is their content: the tooltip's `content` attribute and the hover card's `trigger` slot are removed, and so are the `tooltip` and `card` parts, the element being the popover itself. In React, `Tooltip` and `HoverCard` take `htmlFor` and their content as children.
- 898133d: `lu-value-change` on `lu-select` and `lu-segmented`, and `lu-selected-change` on `lu-multi-select`, now fire before the element updates its value, and `preventDefault()` keeps the current value. Every other `lu-*` event is no longer cancelable.
- 14816de: Every element now changes the state the user changes, after a cancelable event that says why. `lu-dialog`, `lu-sheet` and `lu-confirm-dialog` close themselves on Escape, the backdrop, the close or cancel button; `lu-tooltip` and `lu-hover-card` gain an `open` property and fire `lu-open-change`. To keep control, cancel `lu-open-change` and set `open` yourself. Every `lu-*-change` detail carries a `source` (`escape`, `outside`, `close-button`, `cancel`, `trigger`, `panel`, `form`, `option`, `clear`). The React components are controlled when given `open`, `value` or `selected`, and uncontrolled without; `onOpenChange` and the value callbacks receive the source as a second argument. `@slashome/lumen/vue` exports `LuDialog`, `LuSelect` and the other stateful elements with `v-model:open`, `v-model:value` and `v-model:selected`.
- cfe4029: Add `<lu-combobox>` (`@slashome/lumen/combobox`), a text field on the ARIA combobox pattern that filters its `options` as the user types, picks one value or, with `multiple`, several drawn as removable tags, and with `creatable` offers a text no option matches as a new value. With `skip-filter` and `loading`, the application loads the options when `lu-search` (`{ query }`, fired on every change of the text) tells it what was typed. It fires a cancelable `lu-value-change` with the new value, a string or an array with `multiple`, and the sources `option`, `create`, `remove` or `clear`; `ValueChangeSource` gains `create` and `remove`. With a `name`, its values are submitted with its form. `label` is required. React gets `Combobox`, Vue `LuCombobox` with `v-model:value`. Three new required keys in `LumenMessages`: `comboboxNoResults`, `comboboxCreate`, `comboboxResults`.
- 898133d: Add the CSS feedback classes `.lu-alert` with its `--info`, `--success`, `--warning` and `--danger` statuses, `.lu-skeleton` with `--text` and `--circle`, and `.lu-progress` on the native `<progress>`, determinate or indeterminate.
- 5cb7154: Add `<lu-file-drop>` (`@slashome/lumen/file-drop`): a zone to drop files or choose them with the system picker, listing them with a remove button each. It fires a cancelable `lu-files-change` (`{ files, source }`, sources `drop`, `picker`, `remove`) and `lu-reject` for files that `accept` or a missing `multiple` refuses, and it never uploads. With a `name`, its files are submitted with its form. `label` is required. Six new required keys in `LumenMessages`: `fileDrop`, `fileBrowse`, `fileRemove`, `filesAdded`, `fileRemoved`, `fileRejected`. `@slashome/lumen/testing` stands in for `ElementInternals.setFormValue` under jsdom.
- 898133d: Add the CSS form classes `.lu-field` (label, hint, error, required mark, choice row), `.lu-textarea`, `.lu-checkbox`, `.lu-radio` and `.lu-radio-card`. `.lu-input` and `.lu-native-select__control` draw `aria-invalid="true"` with a danger border, and `attachLight()` lights checkboxes and radios.
- 15c2c15: Lumen ships no text. Register the generic labels once at start-up with `registerLumenMessages(lang, messages)` (or `app.use(lumen, { messages })` in Vue); `LumenMessages` lists the required keys and `lumenMessageKeys` checks them at run time. `close-label`, `cancel-label`, `clear-label`, the new `label` of `lu-toaster` and `role-description` of `lu-draggable` override the registry; `confirm-label` is required on every `lu-confirm-dialog`, which no longer has `close-label`. A missing label logs a console error and renders nothing. `lu-pickup`, `PickupDetail`, React `onPickup` and Vue `onLuPickup` are removed: `lu-draggable` calls its `lu-drag-area` directly.
- 630083d: Add the CSS class `.lu-date-input` for the native `<input type="date">`, `"datetime-local"` and `"time"`: the control height, the colors of the inputs, `aria-invalid="true"` in the danger color, and a picker button in the muted color where the browser draws one. The open calendar stays the browser's.
- 898133d: Add `<lu-tabs>` on the ARIA tabs pattern, at `@slashome/lumen/tabs` and as `Tabs` in React: arrows, `Home` and `End`, automatic activation or `manual`, and a cancelable `lu-value-change`. Add the CSS classes `.lu-breadcrumb` and `.lu-pagination`.
- 8963b2c: The error state has one name, `danger`: `.lu-button--danger` (React `variant="danger"`), the toast kind `danger` and `toast.danger()`. `.lu-button--destructive`, `variant="destructive"`, the toast kind `error` and `toast.error()` still work and are deprecated, to be removed in the next major version.
- ab0bbd2: `label` is required on `lu-select`, `lu-multi-select`, `lu-segmented` and `lu-tabs`: required in the React and Vue types (`SelectElement`, `LuSelect` and the global `lu-select` component included), marked required in `custom-elements.json`, and a console error when it is missing. `lu-dialog`, `lu-sheet` and `lu-confirm-dialog` log an error without `heading` or a `heading` slot. `LumenMessages` gains a required `confirm` key: `confirm-label` on `lu-confirm-dialog` and `confirmLabel` in React become optional and win over it.
- c9a8105: `lu-segmented` takes `skip-tab`, a boolean attribute that leaves its buttons out of the tab order (React `skipTab`). `focusable="false"` and the React `focusable={false}` still work and are deprecated, to be removed in the next major version.
- 283f73c: Add the CSS class `.lu-stepper`, a step indicator on an `<ol>`: the application puts `aria-current="step"` on the current `.lu-stepper__step`, the steps before it are drawn done with a check, the next ones with their number, and a done step may hold a link. `.lu-stepper--vertical` stacks the steps.
- fb3d0f0: Add the CSS class `.lu-tag` for a value shown as a tag, and `<lu-tag removable>` (`@slashome/lumen/tag`), a tag with a remove button that fires `lu-remove` (`{ value }`, not cancelable) on a click, Delete or Backspace, and leaves its removal to the owner. React gets `Tag`, which draws the class without `onRemove` and the element with it. One new required key in `LumenMessages`: `tagRemove`, which names the remove button from the text of the tag.

### Patch Changes

- 069a4d2: Describe each component by how it is used, `CSS class · no JavaScript` or `Custom element · import '@slashome/lumen/<name>'`.
- a629c91: Under the jsdom shims of `@slashome/lumen/testing`, a tooltip, a hover card and the toaster now close: the popover they hide was still reported open.
- 198f248: `tokens.css` gives every color derived with `oklch(from …)` a fallback for browsers without relative color syntax: there, `--lu-color-primary`, `--lu-color-primary-foreground`, `--lu-color-ring`, `--lu-color-accent` and `--lu-color-highlight` take the values of the default theme, so dark mode keeps its primary fills and text on them stays readable. Current browsers still follow `--lu-theme-primary` and `--lu-theme-secondary`.
- 898133d: Ship `CHANGELOG.md` in the package.

## 0.1.0

### Minor Changes

The first version of Lumen, the design system of slashome, extracted from the `shared/ui` of Ariane. One implementation serves React, Vue, Svelte and plain HTML.

- [#1](https://github.com/slashome/lumen/pull/1): design tokens in DTCG JSON, built by Style Dictionary into `tokens.css`, with a two-color theme (`--lu-theme-primary`, `--lu-theme-secondary`) and a dark mode set at runtime. CSS classes for what has no state (button, badge, input, native select, switch, kbd, data table, page states, utilities); custom elements for what has one (`lu-dialog`, `lu-sheet`, `lu-confirm-dialog`, `lu-select`, `lu-multi-select`, `lu-tooltip`, `lu-hover-card`, `lu-segmented`, `lu-toaster`, `lu-markdown`, `lu-highlight`, `lu-drag-area`). `lu-icon` draws icons embedded at build time under semantic names, with no network request. React wrappers in `@slashome/lumen/react`, Vue types in `@slashome/lumen/vue`. Everything public is prefixed `lu-`.
- [#2](https://github.com/slashome/lumen/pull/2): every semantic token carries a description, shown on the Tokens page of the Storybook, and the build fails on a token without one. The docs no longer contradict the `lu-` prefix.
- [#3](https://github.com/slashome/lumen/pull/3): one entry point per element (`@slashome/lumen/select`) and a precise `sideEffects`, so importing one element no longer ships Markdown or drag and drop. Every existing export path still works.
- [#4](https://github.com/slashome/lumen/pull/4): every element documents its public API in JSDoc; `custom-elements.json` feeds the Storybook props tables and the React and Vue types. The Storybook is sorted by use. Tokens and element APIs can be deprecated for at least a minor version before their removal in a major.
- [#5](https://github.com/slashome/lumen/pull/5): every story runs as a browser test in Chromium and fails on an accessibility violation. Fixes a draggable picked up by Space that dropped in place, and a quickly reopened dialog that closed itself.
